# نظام مجمع أم القرى

نسخة تأسيسية محلية بـ Next.js، React وSQLite. تشغيل Node.js 22 أو أحدث.

## التشغيل

```sh
npm install
npm run dev
```

افتح http://127.0.0.1:3000 وأنشئ حساب المالك عند أول تشغيل. لا توجد كلمة مرور افتراضية. قاعدة البيانات المحلية في data/clinic.sqlite ولا تُرفع إلى Git.

## المنفذ حاليًا

- إعداد مالك، دخول بجلسة HttpOnly، كلمات مرور scrypt، حسابات الموظفين.
- أدوار قابلة للتعديل، صلاحيات مستقلة لكل وحدة وإجراء، تحقق على السيرفر وسجل تدقيق.
- تسجيل المرضى، تنبيه الهاتف المكرر مع تأكيد تسجيل فرد آخر.
- مواعيد مع كشف التضارب وتسجيل أوقات الوصول والخدمة وسبب الإلغاء.
- توثيق سريري أولي بنص حر، اعتماد وقفل وإضافة موثقة؛ التوثيق مقيد بالممارس المؤهل.
- فواتير ودفع جزئي، مهام ودليل إتمام.

## متبقي قبل اكتمال المرحلة الأولى أو التشغيل الفعلي

توسيع قوالب التقييم حسب التخصص، مقارنة القياسات وتطور الحالة وإغلاقها، التقويم المرئي ونقل المواعيد وقائمة الانتظار، حدود اعتماد الخصومات والاسترداد وإقفال الصندوق وربط بيع الباقات بالفواتير، إرفاق المستندات، حدود نطاق البيانات لكل دور، مهام متكررة وتصعيد آلي، لوحة مؤشرات، تقييد محاولات الدخول، استعادة الحسابات وإبطال الجلسات، النسخ الاحتياطي واختبارات الاستعادة. الوحدات المنفذة بالمراحل اللاحقة موضحة أدناه؛ ما زالت نسخًا أولية.

استخدم بيانات اختبار فقط. هذه ليست نسخة جاهزة للاستخدام الطبي أو للإطلاق. سجل التدقيق تطبيقي ولا يحمي من تعديل مسؤول قاعدة البيانات. SQLite محلي لبيئة التطوير ويتطلب اختيار استضافة وتخزين دائم قبل النشر.

## ديمو بدون تسجيل

افتح http://127.0.0.1:3000/?demo=1 أو اضغط «استعراض الديمو بدون تسجيل». بيانات وهمية في SQLite داخل الذاكرة منفصلة تمامًا عن قاعدة المجمع، مع تبديل دور المالك والأخصائي والاستقبال والمساعد. التغييرات مشتركة بين زوار الديمو وتُصفّر عند إعادة تشغيل السيرفر. الديمو متاح في التطوير فقط؛ للإتاحة المقصودة في بيئة إنتاج تجريبية اضبط CLINIC_DEMO=1. لا يستخدم الديمو حسابات حقيقية أو بيانات مرضى حقيقية.

## المرحلة الثانية — النسخة التشغيلية الأولية

أُضيفت الأجهزة والعدادات، بلاغات الصيانة، الأصناف وحركات الاستلام والصرف والتسوية، المصروفات، الالتزامات والتراخيص. تستخدم الصلاحيات القائمة للأجهزة والمخزون والمالية والالتزام. العمليات محفوظة في SQLite، مع معاملات ذرية تمنع تجاوز العداد أو الرصيد. تسوية المخزون تحتاج صلاحية اعتماد.

المتبقي قبل اكتمال المرحلة الثانية: إرفاق الملفات، رأس الجهاز ككيان مستقل وسجل استبدال، حدود تنبيه قابلة للضبط وتنبيهات ومهام تلقائية وتصعيد، قطع الغيار وتكلفة ومدة توقف الصيانة، وجدولة الاستحقاق التالي بعد السداد والتجديد مع حفظ النسخ التاريخية. حقل التكرار محفوظ حاليًا ولا يشغّل أتمتة دورية. تاريخ انتهاء الترخيص يُصنّف للعرض بحد 30 يومًا أولي.

الديمو الموسّع يتضمن 1,153 سجلًا وهميًا: 150 مريضًا، 180 موعدًا، 240 توثيقًا سريريًا، 120 فاتورة، 65 مهمة، 24 جهازًا، 35 بلاغ صيانة، 40 صنفًا، 83 حركة مخزون، 50 مصروفًا، 24 التزامًا، 28 وثيقة، 28 مستخدمًا تجريبيًا و86 حدث تدقيق. المبالغ والقيم أمثلة عرض وليست أسعار المجمع. أرقام التواصل الإضافية معرفات DEMO وليست بيانات اتصال حقيقية. يوجد زر فتح/قفل كل أقسام القائمة.


## المرحلة الثالثة — نسخة أولية محلية
تمت إضافة تقديرات تكلفة الخدمات وهامشها، الحملات والاستفسارات بمراحل متابعة، الشكاوى مع دليل إلزامي للإغلاق، تقييمات الرضا، وتقارير تشغيلية تُقيّد بصلاحيات الأقسام. أضيفت 220 سجلاً وهمياً لهذه الوحدات.
التكلفة تقديرية يدوية؛ لا تزال تكلفة الجلسة الفعلية وربط الحملات بالمريض والتحصيل واحتساب العائد والإجراءات الوقائية المستقلة والتصدير حسب الصلاحيات قيد التنفيذ. المرحلة الرابعة تحتاج تحديد مزودي التواصل والدفع قبل ربط الخدمات؛ لا توجد عمليات إرسال أو دفع خارجي في هذه النسخة.

المرحلة الرابعة: أضيف أساس محلي لطابور التكاملات يمنع تكرار الطلب بالمفتاح نفسه، وسجل للمالك يعرض عمليات وهمية بحالة «بانتظار تحديد المزود». لا يوجد ناقل شبكة أو webhook أو معالجة دفع حقيقية؛ لا تُعرض تفاصيل المحتوى في واجهة السجل.

باقات الجلسات: إنشاء باقة للمريض والخدمة والصلاحية، وربطها برقمها عند حجز الموعد، وخصم جلسة مرة واحدة عند إتمام الموعد ضمن معاملة ذرية. الصلاحية تُراجع بتاريخ الموعد، والرصيد المستنفد يمنع الإتمام. لا يوجد رد تلقائي للجلسة عند إعادة فتح الموعد أو إلغائه بعد الإتمام؛ يلزم مسار تصحيح واعتماد لاحق. الباقة لا تُنشئ فاتورة تلقائيًا في هذه النسخة.

التقييم المنظم: الأعراض والفحص وقياس الألم 0–10 ومراجعة العلامات التحذيرية، مع توثيق إجراء إلزامي عند رصدها. الخطة تتطلب أهدافًا وتدخلات وتكرارًا ومدة وموعد إعادة تقييم. تُربط السجلات الجديدة بحالة فريدة للمريض والممارس والعنوان. لا توجد قائمة تشخيصية آلية أو مقارنة زمنية للقياسات بعد.
المالية: سجل تحصيل واسترداد مع وسائل الدفع وسبب الاسترداد، وسجل خصومات. الاسترداد والخصم يحتاجان finance.approve، والتحصيل finance.edit، وتُحدّث الفاتورة والسجل معًا بمعاملة ذرية. حدود مبلغ الموافقة وإقفال الصندوق لم تُنفذ بعد. بيانات التحصيل القديمة في قاعدة المجمع لا تتحول تلقائيًا إلى حركات تاريخية؛ التحويل مُطبق على البيانات الوهمية فقط.

إقفال الصندوق: مطابقة تحصيل واسترداد ومصروفات النقد ليوم منتهٍ بتوقيت سلطنة عمان (Asia/Muscat)، مع رصيد افتتاحي ونقد معدود وسبب لأي فرق. الإقفال يحتاج اعتماد المالية ولا يقبل التعديل؛ المصروفات النقدية لليوم المقفل محمية. تُحفظ أوقات الحركات بالتوقيت العالمي، وتُجمع ضمن حدود اليوم المحلي في عمان. مراجعة فروق الإقفال بمسار تصحيح مستقل ما زالت مطلوبة. حدود الخصم والاسترداد قابلة لضبط المالك؛ القيمة الافتراضية صفر والموظف المعتمد لا يتجاوز الحد، والمالك ينفذ العمليات الأعلى. لا يوجد طلب موافقة معلّق بعد. الديمو يتيح اختيار الأدوار الثلاثة عشر.

نشر Vercel معد للديمو فقط: CLINIC_DEMO=1 وCLINIC_DEMO_ONLY=1، بيانات SQLite داخل ذاكرة كل نسخة تشغيل وقد تختلف التعديلات بين النسخ وتُصفّر عند إعادة تشغيلها. إنشاء الحسابات الحقيقية والدخول بها معطلان في هذا الوضع. جلسة الديمو قابلة للاستعادة على نسخة تشغيل أخرى وتختار دورًا تجريبيًا فقط. لا تستخدم بيانات مجمع حقيقية في هذا النشر.

التكامل والتسليم المستمران: GitHub Actions يشغّل npm ci والاختبارات والبناء على كل رفع إلى main وكل طلب دمج. Vercel مرتبط بالمستودع، وينشر main تلقائيًا؛ أمر بناء Vercel يشغّل الاختبارات أولًا فلا ينشر نسخة تفشل في الاختبارات أو البناء، ويظل آخر نشر ناجح متاحًا. الاختبارات تستخدم قاعدة داخل الذاكرة.

ربط موارد الجلسة: مسودة Session يمكن أن تحتوي على عدة أجهزة وأعداد استخداماتها وعدة أصناف وكمياتها. عند اعتماد الممارس لسجله يُخصم العداد والمخزون مع قفل السجل في معاملة واحدة؛ العطل أو نقص الرصيد يمنع الاعتماد ويرجع كل التغييرات. لا يتكرر الخصم لسجل معتمد. التصحيح بعد الاعتماد لا يعيد المخزون تلقائيًا؛ تُجمع الصفوف المكررة لنفس المورد قبل الخصم. الديمو يتضمن مسودة «تجربة استهلاك الموارد» لدى أخصائي العلاج الطبيعي.

دفعات المخزون: الاستلام يتطلب رقم دفعة ويدعم صلاحية اختيارية. الصرف يستهلك الدفعات الصالحة حسب الأقرب انتهاءً ثم غير المؤرخة، ويمنع صرف المنتهي بتوقيت عمان. سجل الحركات يعرض الدفعات والكميات المصروفة، وصفحة مستقلة تعرض المنتهي والقريب خلال 30 يومًا. الرصيد القديم يُنقل إلى دفعة افتتاحية مع الصلاحية القديمة إن وجدت. التسوية المعتمدة تخفض الدفعات المنتهية أولًا؛ التصنيف لا يمثل تنبيهًا آليًا. التكلفة لا تزال متوسط تكلفة الصنف؛ تخصيص التكلفة الفعلية لكل دفعة في الربحية لاحق.

المشتريات: وحدة مستقلة بصلاحيات purchasing القابلة للتعديل من المالك. مسؤول المخزون ومدير التشغيل يملكان العرض/الإنشاء/تعديل مسوداتهما، والمالك صلاحية الاعتماد والاطلاع العام. الطلب متعدد الأصناف، إجماليه محسوب على السيرفر؛ لا تعدل المسودة إلا بواسطة منشئها، ويقفل الإرسال البنود. الاعتماد أو الرفض يحتاج شخصًا آخر بصلاحية اعتماد، والرفض يلزم سببًا. المعتمد يتحول لأمر شراء واحد فقط. الاستلام الجزئي لكل صنف يضيف دفعة للمخزون ويحفظ المرجع، يمنع تجاوز المتبقي وإعادة تنفيذ معرف الاستلام نفسه، ويقفل الأمر بعد الاستلام الكامل. القرارات والاستلام في سجل التدقيق. الديمو يتضمن 12 طلبًا وحالات موافقة ورفض وأوامر واستلام جزئي.

حدود دورة المشتريات الحالية: سعر أمر الشراء يساوي السعر التقديري المعتمد في الطلب، ولا توجد مرحلة عروض أسعار أو تعديل سعر مورد بعد الموافقة؛ لا تنشأ فاتورة مورد أو دفعة مالية. الاستلام يتم لصنف/دفعة في كل عملية مع تكرار العمليات لاستلام بقية البنود. نطاق البيانات حاليًا طلبات المنشئ أو جميع الطلبات لصاحب صلاحية الاعتماد؛ صلاحية الأقسام وحدود مبلغ الاعتماد والمرفقات وسحب الطلب وإعادة المراجعة وإلغاء/إغلاق المتبقي ما زالت لاحقة.
