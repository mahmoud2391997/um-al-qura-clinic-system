Task 7: storage interface and quarantine
- Added a database storage adapter (read/write) and injectable storage interface for a future S3-compatible adapter. No external store was configured. Added an optional ClamAV INSTREAM Unix-socket hook via CLINIC_CLAMAV_SOCKET; absent socket, scanner errors and unknown results remain Unscanned.
- Both general and purchasing attachment downloads now require a Clean scan and a matching SHA-256 content digest. Existing attachments without scan records are quarantined. Infected files cannot download. Upload payloads cannot select a scanner or supply a trusted status. Existing PDF/PNG/JPEG, 2 MiB and 10-per-reference limits remain.
- `node scripts/scan-attachments.mjs` rescans stored objects using the explicitly configured socket. It reports counts only. In-process fake scanner injection is used solely in tests/fixtures; no bypass environment flag exists.
- Verified: 161/161 dual-database tests, including unavailable/infected/clean scanner, quarantine, altered bytes, fake storage adapter and file limits. Existing happy-path tests now explicitly install a synthetic clean scanner.
- Not verified: a real ClamAV daemon/signature update policy, S3, scanner capacity/latency, cross-store transactional recovery, existing production-file rescanning or real devices. The current optional storage API keeps database metadata; remote-object lifecycle is future integration work.
